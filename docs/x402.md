# x402-style flow (agent payments)

AQB is the payment leg of a 402 handshake. No accounts, no API keys for the money path.

## Client agent
1. `GET https://svc.example/a2a/task` → `402` with headers in [MARKETING §3](MARKETING.md).
2. Read `X-AQB-PayTo`; assert `AgentRegistry.isAgent(payTo)` is true, else abort.
3. Pay: `token.transfer(payTo, price)` (or stealth if you want the payer hidden).
4. Retry with `X-AQB-Tx: <hash>`.
5. Service verifies the receipt: `Transfer(from=payer, to=payTo, value>=price)` in that tx, block depth ≥ 1.

## Server agent
```js
const tx = await provider.getTransactionReceipt(req.header("x-aqb-tx"));
const logs = tx.logs.filter(l => l.address.toLowerCase() === TOKEN);
const paid = logs.some(l => {
  const [from, to, value] = token.interface.parseLog(l).args;
  return to.toLowerCase() === PAYTO && value >= PRICE;
});
if (!paid) return res.status(402).end();
```
Refund policy is the server's choice; the contract always lets the payer redeem unused AQB for USDC.

## Rules
1. Price must be in AQB, integer 1e18.
2. Never accept a tx whose `to` is a non-agent.
3. Wait 1 block; Base finality for this use case is the canonical sequencer ordering.
4. Replay: bind one tx hash to one task id.

## Stealth variant
Payer derives `stealthFor(recipientKemKey)`, pays that address, and announces it. Server scans announcements with `stealthCheck` and matches `viewTag` first. Payer identity never appears on chain.
